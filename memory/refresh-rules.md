# 记忆刷新规则

## 刷新目标

- 移除过时记忆。
- 合并重复记忆。
- 标记不确定记忆。
- 提升有用候选记忆。
- 归档无效记忆。

## 正式写入者

正式记忆由 Memory 记忆智能体管理。

## Memory 收尾门 M0-M3

所有工作流关闭前都必须给出 Memory 结论。Memory 结论可以是“不写记忆”，但不能省略判断过程；具体工作流选择见 [playbook](../playbook.md)。

固定档位名称：`M0 不写记忆`、`M1 记忆检查`、`M2 候选记忆`、`M3 正式记忆`。

| 档位 | 名称 | 何时使用 | 必做动作 | 禁止事项 |
|---|---|---|---|---|
| M0 | 不写记忆 | `WF-01` 快速问答、只读解释、一次性判断，且没有文件变化、项目事实变化或恢复价值 | 直接记录 `M0：无长期恢复价值` 或同等结论 | 不创建候选；不写正式记忆；不得用于已经产生项目事实、规则变化、Agent 指引变化或多 Agent 交接的任务 |
| M1 | 记忆检查 | 小修、轻量验证、需求澄清早期，可能没有长期事实但需要关闭前确认 | Lead 或 Memory 回答收尾门问题，并记录“无需记忆”或升级到 M2 的原因 | 不得跳过原因；不得把未经筛选的内容直接写入正式记忆；不得把临时过程当成候选 |
| M2 | 候选记忆 | `WF-07/08/10/11/12` 或其他非平凡任务产生了可能长期有用但仍需筛选的恢复事实、教训、约束或交接 | 写入 `memory/candidates/` 或在任务交接中列出候选，由 Memory 按本规则筛选 | 不得写入原始日志、大段输出、临时过程、未验证事实或敏感内容；不得绕过 Doc 把项目事实写成正式记忆 |
| M3 | 正式记忆 | 已验证、稳定、未来恢复任务确实需要的长期事实，且来源、范围、证据和过期条件清楚 | 由 Memory 写入根 `memory/` 下正式记忆或对应 Agent 记忆，并记录来源任务、验证证据和适用范围 | 非 Memory 不得正式写入；不得写入无验证事实、临时执行细节、日志、凭证、用户禁止记录内容或可由 `project/` / KB 稳定承载的知识 |

### 收尾门判断问题

M1-M3 至少回答：

1. 是否产生共享记忆。
2. 是否产生 Agent 独立记忆。
3. 是否产生项目事实，应交给 Doc。
4. 是否产生上下文恢复材料。
5. 是否无需记录，原因是什么。

M0 可以只给出“无长期恢复价值”的结论；一旦答案涉及项目事实、恢复材料、候选或正式记忆，必须升级到 M1-M3。

## 与 Doc / project 的边界

- Memory 只沉淀任务恢复所需的长期事实、Agent 独立记忆、上下文恢复材料和记忆候选。
- `project/` 由 Doc 维护；项目画像、需求、计划、架构、命令、验证、风险、接口契约、UI 风格和项目图谱变化交给 Doc 合并。
- 稳定可复用知识、知识图谱和 KB 候选交给 Doc；Memory 不直接写正式知识库。
- Memory 可以在候选或正式记忆中链接 `project/` 来源，但不得复制项目文档来替代 Doc 更新。
- Claude 原生记忆、临时聊天上下文或工具缓存不能替代 AI-Teams 的 `memory/` 文件体系。

## 刷新触发

- 用户要求读取、刷新、压缩或恢复记忆。
- 长任务阶段结束，Lead 判断后续需要恢复点。
- 多 Agent 交接完成，需要沉淀稳定任务状态。
- 任务失败重试后产生可复用教训。
- 项目初始化或升级产生长期稳定事实。
- QA 验收后确认某些约束、命令或风险对后续任务长期有效。
- Hook 提示上下文恢复材料达到压缩阈值。
- Memory 准备写入正式记忆时，发现候选、恢复材料或旧记忆需要压缩、合并或归档。

## 候选进入流程

1. 来源 Agent 将候选写入 `memory/candidates/` 或任务交接。
2. Hook 或手动压缩产生的摘要先进入 `memory/conversations/`，不得直接进入正式记忆。
3. Memory 检查来源、时间、任务、关联文件和验证证据。
4. Memory 按保留策略判断：共享记忆、Agent 独立记忆、继续候选、归档或拒绝。
5. 正式写入后记录来源摘要、写入位置和未采纳原因。
6. 如候选更适合知识库，交给 Doc 进入 `kb/candidates/`，不得由 Memory 直接写正式知识库。

## 写入前检查

Memory 写入正式记忆前必须同时检查：

1. 是否需要先生成上下文压缩摘要，规则见 [context-compression](./context-compression.md)。
2. 是否有旧候选或旧恢复点已经可以归档，规则见 [retention-policy](./retention-policy.md)。
3. 是否有内容其实属于 `project/`，应交给 Doc 合并而不是写入正式记忆。
4. 是否有内容属于可复用知识，应交给 Doc 进入知识候选。
5. 是否含敏感内容；含敏感内容必须拒绝写入。

## 共享记忆与独立记忆判断

| 判断问题 | 写入位置 |
|---|---|
| 所有 Agent 恢复都需要吗？ | `memory/MEMORY.md` |
| 只对某个 Agent 长期有效吗？ | `memory/agents/<agent>/MEMORY.md` |
| 只是当前任务恢复材料吗？ | `memory/conversations/` |
| 尚未验证但可能长期有用吗？ | `memory/candidates/` |
| 是稳定复用知识而不是恢复事实吗？ | 交给 Doc 处理 |

## 候选评分

| 维度 | 高价值表现 | 低价值表现 |
|---|---|---|
| 恢复价值 | 中断后能直接恢复任务 | 只描述一次性聊天过程 |
| 稳定性 | 来自需求、架构、用户规则或已验证结果 | 未验证猜测或临时判断 |
| 作用范围 | 多个 Agent 或未来任务都会用到 | 只对当前一步有用 |
| 可摘要性 | 能压缩成清晰事实 | 需要保留大段上下文才有意义 |
| 安全性 | 不包含敏感内容 | 含密钥、token、证书、`.env` 内容 |

## 正式写入格式

正式记忆应使用短条目，包含：

- 日期或阶段。
- 来源任务或来源文件。
- 稳定事实。
- 适用范围。
- 如有必要，附过期条件。

## 拒绝写入

以下内容必须拒绝进入正式记忆：

- 原始日志、完整会话、大段代码、终端长输出。
- 未经验证的推测。
- 可以通过索引或知识库稳定获取的百科式信息。
- 敏感文件内容、凭证、密钥、token、证书、私有环境变量。
- 用户明确要求不要记录的内容。
