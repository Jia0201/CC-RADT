# PD 内容风格

## PRD 结构

- 什么时候使用：生成需求文档、需求摘要、需求补充或需求评审稿时。
- Codex 生成内容时要遵守：优先包含背景、目标、范围、非目标、用户角色、用户路径、业务规则、验收标准、风险和待确认问题。

## 用户故事

- 什么时候使用：需求需要按用户角色和价值拆分时。
- Codex 生成内容时要遵守：表达“作为谁、想完成什么、获得什么价值”；不写成组件任务或技术改造项。

## 验收场景

- 什么时候使用：需求需要 QA 或 Dev 直接判断行为正确性时。
- Codex 生成内容时要遵守：场景应包含前置条件、触发动作和期望结果；结果必须是用户、系统状态或数据层面可观察的事实。

## 语言风格

- 什么时候使用：所有 PD 文档、需求条目和评审意见。
- Codex 生成内容时要遵守：使用明确、短句、可验证表达；避免“尽量”“适当”“完善体验”“相关逻辑”等无法验收的词。

## 表格与清单

- 什么时候使用：多角色、多规则、多字段、多状态、多验收项需要对比时。
- Codex 生成内容时要遵守：表格列名要表达审查维度；清单条目要能单独判断，不把多个验收点混成一条。

## 待确认问题

- 什么时候使用：需求输入不足但需要继续交接或评审时。
- Codex 生成内容时要遵守：问题要可回答、可归属、可影响决策；不要写“是否合理”这类空泛问题。
