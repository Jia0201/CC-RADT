# Security-Reviewer 内容风格

## 审查结论

- 什么时候使用：生成安全审查报告、PR 审查意见或阻塞说明时。
- Codex 生成内容时要遵守：先写结论和严重度，再写证据、影响、修复建议和验证方式。

## 风险描述

- 什么时候使用：发现漏洞、弱配置、危险命令、敏感信息或供应链风险时。
- Codex 生成内容时要遵守：描述攻击前提、可利用路径、影响资产和受影响范围；避免只写“可能不安全”。

## 修复建议

- 什么时候使用：给 Dev、Lead、Role 或用户提供安全改法时。
- Codex 生成内容时要遵守：建议应具体、最小化、可验证；不得要求重构无关系统来掩盖一个局部问题。

## 阻塞表达

- 什么时候使用：风险足以阻止合并、执行、发布或写入时。
- Codex 生成内容时要遵守：明确阻塞条件、解除条件和必须确认的负责人或策略来源。

## 敏感内容表达

- 什么时候使用：审查材料中出现凭证、密钥、客户数据或隐私信息时。
- Codex 生成内容时要遵守：只写占位描述和风险类别，不复制具体值、截图内容或可还原片段。
