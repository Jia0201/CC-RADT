# Role 工程规则

## 职责边界

- 什么时候使用：两个或多个 Agent 对同一类任务都有描述、任务失败显示边界不清或用户要求调整角色时。
- Codex 生成内容时要遵守：角色职责必须说明输入、输出、拥有的文件范围和不负责事项；不得制造重叠却不说明仲裁关系。

## 角色健康检查

- 什么时候使用：Agent 反复误读任务、找错入口、遗漏验证、越权修改或需要频繁人工纠偏时。
- Codex 生成内容时要遵守：先区分任务问题、计划问题、上下文问题、工具问题和角色问题；不能把单次失败直接归因于角色设计。

## 组件同步

- 什么时候使用：更新 `agents/<agent>/` 下主入口、role、workflow、memory、kb、skills、mcp 或 playbook 相关说明时。
- Codex 生成内容时要遵守：组件文件之间的职责、入口、能力和边界必须一致；索引链接不能指向过期结构。

## Skills 与 MCP 绑定

- 什么时候使用：角色需要新能力、移除能力、限制工具使用或补充工具说明时。
- Codex 生成内容时要遵守：绑定必须说明适用场景、风险和职责匹配关系；不得把高权限工具作为默认便利能力。

## 安全边界

- 什么时候使用：角色变化影响删除、覆盖、敏感文件、高风险命令、外部网络、MCP、Hook 或凭证处理时。
- Codex 生成内容时要遵守：安全策略和 playbook 优先；角色说明不得扩大未授权权限。

## 长期结构变更

- 什么时候使用：新增 Agent、拆分 Agent、合并 Agent、改变团队协作方式或引入长期治理规则时。
- Codex 生成内容时要遵守：说明变更原因、影响范围、迁移关系和索引更新点；需要长期决策记录时应交给 Doc 判断 ADR。

## 运行期指引维护

- 什么时候使用：新文件、新规则、新 Hook/Tools、项目管理职责变化或复盘显示 Agent 指引过期时。
- Codex 生成内容时要遵守：维护知识应写清触发原因、影响 Agent、需同步组件和验证方式；不把临时 workaround 写成永久职责。
