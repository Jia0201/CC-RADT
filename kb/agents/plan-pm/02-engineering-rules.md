# Plan-PM 工程规则

## 需求到任务追溯

- 什么时候使用：把 PD 需求、用户请求或修复目标拆成执行项时。
- Codex 生成内容时要遵守：每个任务必须能追溯到目标、需求条目、风险或验收项；不得生成没有来源的任务。

## 任务粒度

- 什么时候使用：任务过大、跨多个模块、跨多个 Agent 或验收困难时。
- Codex 生成内容时要遵守：任务应有单一主目标、明确输入输出和可验证完成条件；不能把调查、实现、验证混成不可管理的大块。

## 依赖排序

- 什么时候使用：任务之间存在数据、文件、接口、文档、测试或安全依赖时。
- Codex 生成内容时要遵守：明确前置条件、阻塞关系和同步点；不能让后续任务依赖隐性假设。

## 并行边界

- 什么时候使用：多个 Agent 或 worker 同时修改项目时。
- Codex 生成内容时要遵守：说明文件范围、所有权、交接物和冲突风险；不得让多个执行方无边界地修改同一批文件。

## 验证计划

- 什么时候使用：任务涉及代码、文档、配置、索引、迁移或用户可见行为时。
- Codex 生成内容时要遵守：每个任务都应包含最小验证方式；无法运行验证时要给出替代审查方式和残余风险。

## 风险控制

- 什么时候使用：存在删除、覆盖、权限、敏感信息、迁移、回滚、外部依赖或范围不确定时。
- Codex 生成内容时要遵守：风险要写清影响、概率来源、阻塞条件和缓解方式；高风险项必须显式交给安全或负责人审查。

## 交接结构

- 什么时候使用：计划需要被 Lead、Dev、QA、Doc、Security-Reviewer 或 Memory 使用时。
- Codex 生成内容时要遵守：交接应包含目标、范围、输入、输出、文件、验收、依赖和风险；不写只有作者自己能懂的上下文。
