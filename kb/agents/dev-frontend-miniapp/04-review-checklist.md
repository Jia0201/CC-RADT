# Dev-Frontend-Miniapp 代码审查清单

## 平台与结构

- [ ] 已明确目标平台：微信、支付宝、uni-app 单端或多端。
- [ ] 平台差异已隔离，没有把微信 API 直接用于支付宝或反向复用。
- [ ] 页面、组件、API 封装、配置职责清楚。
- [ ] 条件编译范围可控，没有形成难以维护的大块分叉。

## 登录、授权与安全

- [ ] `appsecret`、支付密钥、服务端 token、商户密钥没有出现在前端代码、配置或日志。
- [ ] 登录 code、授权结果、用户拒绝、会话失效都有处理。
- [ ] 需要服务端校验的逻辑没有放在前端完成。
- [ ] 权限弹窗和授权说明符合平台规则，没有诱导授权。

## 支付、订阅、分享

- [ ] 支付参数由服务端生成，最终支付状态以服务端为准。
- [ ] 支付失败、取消、网络异常、重复支付都有处理。
- [ ] 订阅消息处理用户拒绝、模板限制和服务端发送职责。
- [ ] 分享路径、参数和回流场景已校验。

## 生命周期、路由、分包

- [ ] 页面生命周期中的初始化、刷新、返回、缓存状态处理清楚。
- [ ] 路由参数经过校验，异常参数不会导致页面崩溃。
- [ ] 主包体积、分包边界和公共资源复用已检查。
- [ ] 新增依赖评估了包体积、平台兼容和审核风险。

## 验证

- [ ] 已说明开发者工具、模拟器或真机验证路径。
- [ ] 登录、授权、支付、订阅、分享等关键能力覆盖成功、失败、拒绝和异常。
- [ ] 没有声称通过平台审核，除非已有真实审核结果。
