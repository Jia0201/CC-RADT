# Dev-Frontend-Miniapp 工程规则

## 平台识别

- 什么时候使用：任何小程序任务开始前，尤其是 uni-app 多端适配任务。
- Codex 生成代码时要遵守：先确认目标平台是微信、支付宝、uni-app 多端还是单端；不得默认所有平台 API、生命周期、组件属性一致。

## 登录与授权

- 什么时候使用：登录、手机号、用户资料、实名、权限弹窗、会话刷新任务。
- Codex 生成代码时要遵守：前端只处理临时凭证、用户授权和状态展示；服务端负责 code 换 session、token 签发和敏感校验。

## 支付

- 什么时候使用：下单、调起支付、支付状态查询、退款入口、订单状态展示任务。
- Codex 生成代码时要遵守：支付参数由服务端生成；支付结果必须以服务端回调或查询为准；前端不得自行判定最终支付成功。

## 订阅消息与分享

- 什么时候使用：订阅消息授权、分享好友、分享朋友圈、模板消息链路任务。
- Codex 生成代码时要遵守：必须处理用户拒绝、模板限制、平台审核要求；不得诱导授权或伪造订阅状态。

## 生命周期与路由

- 什么时候使用：页面进入退出、返回刷新、TabBar、嵌套路由、页面参数传递任务。
- Codex 生成代码时要遵守：按平台生命周期处理初始化和刷新；页面参数要校验；不得依赖浏览器 history 或 DOM 路由行为。

## 分包与包体积

- 什么时候使用：页面增多、主包过大、首屏变慢、接入重资源或第三方库任务。
- Codex 生成代码时要遵守：首屏和公共能力保留在主包，低频页面进入分包；新增依赖必须评估体积和平台兼容。

## 平台差异

- 什么时候使用：微信与支付宝 API、组件、样式、权限和审核要求存在差异时。
- Codex 生成代码时要遵守：差异必须显式隔离；uni-app 条件编译要小范围使用；不得让一个平台的修复破坏另一个平台。

## 测试与验收

- 什么时候使用：涉及登录、授权、支付、订阅、分享、分包、平台 API 的任务。
- Codex 生成代码时要遵守：至少说明模拟器、开发者工具或真机验证路径；支付和授权必须覆盖成功、失败、拒绝和异常。
