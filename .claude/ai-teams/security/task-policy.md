# 任务单与执行方案规则

## 工作流与任务深度

1. Lead 接到需求后先选择工作流编号，再决定任务单和执行方案深度；工作流选择器见 [playbook](../playbook.md)。
2. `WF-01` 快速问答和低风险单点小任务可以轻量执行；若无文件变化、无状态变化、无长期恢复价值，可以不创建完整任务单，但必须在回答、交接或状态事件中保留必要结论。
3. 中大型任务、多文件任务、多 Agent 任务、跨目录任务、需要锁协调或需要串并行编排的任务，必须创建任务单和执行方案。
4. 删除、权限、Hooks、MCP、Skills、settings、敏感命名文件、数据迁移、文件所有权变化、不可逆命令和安全边界变化，自动升级 `WF-11 高风险变更流`。
5. 所有工作流关闭前必须有 Memory 结论，至少记录 M0 不写记忆；M1-M3 按 [refresh-rules](../memory/refresh-rules.md) 执行。

## 任务单规则

1. 非平凡任务必须创建或引用任务单；小任务可轻量执行，但不得绕过工作流编号、风险判断和 Memory 结论。
2. 任务单必须写清目标、上下文、禁止范围、参与 Agent、验收标准和重试状态。
3. 任务单不得包含敏感文件内容。
4. 任务范围变化时，Lead 更新任务单或追加共享决策。
5. 开发、重构、安全、文档治理、初始化、升级、回滚、记忆刷新、知识沉淀等任务必须进入任务单。
6. 任务单必须记录工作流编号、工作流名称、下发方式、参与 Agent、旁路监督 Agent、QA/Doc/Memory/Security/Role 档位，以及是否需要执行方案。

## 执行方案规则

1. 中大型任务、多 Agent、跨目录、多文件锁或需要计划拆解的任务必须创建执行方案。
2. 执行方案必须写清 Agent 分工、执行顺序、文件范围、锁、验收点和风险。
3. Plan-PM 负责执行方案，Lead 负责批准执行路径。
4. Agent 不得绕过执行方案扩展自己的任务范围。
5. 高风险 `WF-11` 默认需要执行方案；如因紧急修复采用轻量方案，必须写明 Security-Reviewer 前置结论、允许范围和验证方式。
6. 执行方案必须记录执行模式、工作流编号、下发方式、旁路监督 Agent 和收尾门状态。

## 工作流关闭规则

- Lead 关闭任务前必须确认实际工作流编号已经记录。
- QA/Doc/Memory/Security/Role 档位必须有对应结论；不参与时记录 Q0/D0/M0/S0/R0 或 skipped 原因。
- Memory 结论是强制关闭条件：M0 无需记录、M1 已检查无候选、M2 已写候选或交接、M3 已写正式记忆、blocked 待处理。
- 高风险任务必须有 Security-Reviewer 前置或复核结论；触发高风险条件后不得降级为普通工作流。
- 工作流范围变化时，Lead 必须更新任务单、执行方案或状态事件，并重新确认档位。

## 状态关联

- 任务单是目标和验收依据。
- 执行方案是计划和分工依据。
- `shared/task-plan.md` 是实时计划状态板。
- `shared/pipeline-status.md` 是 Agent 流水线状态板。
- 交接记录说明阶段完成情况。
- 工作流编号、下发方式、QA/Doc/Memory/Security/Role 档位和 Memory 结论必须能追溯到任务单、执行方案、状态事件、交接或日志。
