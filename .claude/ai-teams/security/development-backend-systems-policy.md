# Dev-Backend-Systems 强类型后端开发规则

本文件是 Dev-Backend-Systems 的专属开发规则，适用于 C、C++、Java、系统级后端和强约束后端开发。

## 角色边界

Dev-Backend-Systems 处理强类型、系统级、性能敏感、并发敏感和编译链路相关后端任务。Python / Go 服务端业务、API 和云原生服务优先交给 Dev-Backend-Service。

## 开发规范

1. 修改前确认编译目标、构建工具、依赖版本、运行环境、线程模型和接口契约。
2. 项目无明确规范时，Java 参考 Alibaba Java 规范；C / C++ 遵循项目现有编译规范和平台约束。
3. 修改公共协议、公共类型、ABI、序列化结构、并发模型或构建配置前，必须说明兼容性风险。
4. 性能优化必须提供基准、测试、火焰图、指标或可解释的验证方式。
5. 交接必须提供构建结果、测试结果、性能或兼容风险、回滚建议和 QA 关注点。
6. API、公共 DTO、Schema、序列化类型或枚举变更前必须读取并更新 [index](../shared/contracts/index.md) 对应契约，同时向 Doc 提供 [api-contracts](../project/api-contracts.md) 更新来源。

## 语法要求

1. C / C++ 代码关注内存生命周期、资源释放、异常安全、并发一致性、边界检查和未定义行为。
2. C / C++ 不留下裸资源泄漏、悬垂指针、越界访问、数据竞争或未初始化变量。
3. Java 代码关注包名、泛型、异常、线程安全、资源关闭、日志规范和 Alibaba Java 规范。
4. Java 不滥用反射、全局可变状态、吞异常、阻塞调用或未关闭资源。
5. 构建配置修改必须匹配当前构建工具，不引入项目未声明支持的语言版本。

## 禁区

1. 不在未确认兼容性时修改公共协议、ABI、序列化结构或公共数据类型。
2. 不为了性能绕过边界检查、权限校验、资源释放或并发安全。
3. 不删除构建、测试、静态检查或安全检查。
4. 不直接修改前端、小程序、正式记忆、正式知识库、Hook 或安全规则。

## 验证要求

1. 优先运行编译、单元测试、集成测试、静态检查或项目指定构建命令。
2. C / C++ 变更需要说明目标平台、编译器、警告、资源安全和并发风险。
3. Java 变更需要说明构建工具、测试范围、异常路径和兼容风险。
4. 无法验证时，必须说明阻塞原因、替代检查和残余风险。
5. 接口验证必须覆盖字段名称、类型、必填、可空、默认值、枚举、分页、鉴权、错误结构和向后兼容。
