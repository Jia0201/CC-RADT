# 错误、接管与回流协议

AI-Teams 不允许 Agent 在报错、无权限、卡断或方向不明时自行连续重试。首次失败即由 Lead 接管诊断，最多允许一次有证据的定向重试。

## 1. 简化状态

| 状态 | 负责人 | 动作 | 退出条件 |
|---|---|---|---|
| 首次执行 | 执行 Agent | 按任务边界执行并保留验证证据 | 成功，或报告失败事实 |
| Lead 接管 | Lead | 检查根因、权限、锁、Owner、安全、范围和环境 | 找到可控根因，或确定必须改派/等待 |
| 一次定向重试 | Lead 指定 Agent | 只改变一个明确变量，保持最小范围并立即验证 | 成功，或再次失败 |
| 回流/改派 | Lead | 改派、拆分、降级、等待用户或停止 | 新路径成立或任务明确阻塞 |

## 2. 立即接管条件

- 工具执行报错、`PostToolUseFailure` 或 `StopFailure`。
- 权限拒绝、认证缺失、环境不可用。
- 敏感文件、删除、不可逆命令、安全阻断。
- 锁、文件所有权或多个 Agent 写入冲突。
- Agent 连续 30 秒没有 Hook 活动或明显卡断。
- Agent 扩大任务范围、处理无关内容或无法说明当前验证目标。
- 需求、字段、接口契约或验收标准不清。

这些情况不消耗“重试次数”，因为必须先由 Lead 判断是否允许继续。

## 3. Lead 接管检查

1. 错误原文和失败工具是什么。
2. 是否缺少权限、外部认证、依赖、网络或运行环境。
3. 是否触及敏感文件、删除、锁、Owner 或安全禁区。
4. Agent 是否仍在本次任务范围，是否访问无关文件。
5. 当前结论是否有文件、日志、测试或交接证据。
6. 下一步是否能缩成一个可验证动作。

检查结果写入 `shared/events/`；需要跨 Agent、等待用户或长期阻塞时创建 `shared/escalations/` 记录。

## 4. 定向重试规则

只有同时满足以下条件才允许一次重试：

- 根因明确，不是猜测。
- 不需要绕过权限、禁用 Hook 或扩大授权。
- 只改变一个变量，例如参数、路径、输入、工具或负责人。
- 有明确验证方式和停止条件。
- Lead 明确指定执行者和范围。

第二次失败后禁止同方向继续尝试。Lead 必须改派、拆分、降级、等待用户或停止。

## 5. 路由

| 问题 | Lead 路由 |
|---|---|
| 需求/验收不清 | PD 澄清，Lead 决策 |
| 计划、依赖、范围冲突 | Plan-PM 重排 |
| 代码或技术实现问题 | 对应 Dev，必要时换 Agent |
| 验证不可信 | QA 重建最小验证 |
| 记忆或恢复问题 | Memory |
| 文档、项目画像、图谱问题 | Doc |
| Agent 职责或指引问题 | Role |
| 权限、安全、锁、删除、敏感文件 | Security-Reviewer + Lead |
| 外部认证或必须用户操作 | 向用户说明最小阻塞条件 |

## 6. 心跳联动

[heartbeat](../supervision/heartbeat.md) 每 10 秒刷新一次可读状态。失败和权限事件会立即给 Lead 追加接管上下文；停滞事件写入 `shared/events/`。Hook 只负责发现和记录，Lead 负责真正的诊断、改派和任务连续性。
