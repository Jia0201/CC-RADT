# Dev-Frontend-Web 工程规则

## 组件拆分

- 什么时候使用：页面逻辑过长、多个区域复用、交互状态复杂、样式难以维护时。
- Codex 生成代码时要遵守：组件只承担清晰职责；容器组件负责取数和编排，展示组件负责渲染和事件输出；不得为了“拆分”制造无意义组件层。

## 状态管理

- 什么时候使用：状态跨页面、跨多个远距离组件、需要缓存、需要统一权限或会话状态时。
- Codex 生成代码时要遵守：局部状态留在组件内；共享状态进入 Pinia、React 状态库或 Angular service；不得把表单临时输入无条件写入全局 store。

## 路由与权限

- 什么时候使用：新增页面、路由守卫、菜单权限、动态路由、登录态跳转任务。
- Codex 生成代码时要遵守：路由必须处理未授权、未登录、404、重定向循环和懒加载；不得只改菜单不改路由权限。

## API 请求

- 什么时候使用：前端联调、数据加载、提交表单、文件上传、鉴权请求任务。
- Codex 生成代码时要遵守：统一请求封装、错误处理、超时、取消或重复提交保护；不得在组件中散落硬编码 base URL、token 或密钥。

## 表单

- 什么时候使用：新增或修改登录、配置、搜索、编辑、批量操作表单时。
- Codex 生成代码时要遵守：表单必须包含校验、错误提示、提交中状态、防重复提交和重置策略；不得只依赖后端校验。

## 用户反馈与可访问性

- 什么时候使用：涉及加载、空状态、错误状态、禁用状态、键盘操作和屏幕阅读器任务。
- Codex 生成代码时要遵守：关键动作有明确反馈；按钮、表单、弹窗、菜单必须可聚焦和可理解；不得用颜色作为唯一状态表达。

## 测试

- 什么时候使用：新增组件、状态逻辑、路由权限、表单提交、关键业务流程时。
- Codex 生成代码时要遵守：至少补充与风险匹配的单元、组件或端到端测试；不得生成无法运行或只断言快照的测试。

## 构建与环境

- 什么时候使用：改动构建配置、环境变量、依赖、代码分割、性能优化任务。
- Codex 生成代码时要遵守：只暴露前端允许暴露的环境变量；构建优化必须检查包体积、缓存、懒加载和兼容目标。
