# PD Agent 知识库

PD 知识库保存需求澄清、产品目标、用户场景、验收标准、范围边界和需求文档结构相关的稳定知识。

## 什么时候使用

- 用户需求模糊，需要澄清目标、角色、场景、边界和成功标准。
- 项目已有规则、业务约束或用户偏好需要进入需求分析。
- 需求需要交给 Plan-PM 拆解前。

## Codex 生成内容时要遵守什么

1. 需求内容要与项目背景、项目画像和项目规则保持一致。
2. 需求文档应包含背景、目标、范围、非目标、用户路径、验收标准、风险和待确认问题。
3. 不把实现细节伪装成用户需求；技术方案属于计划和研发知识。
4. 长期记忆与正式知识库内容要保持候选、验证和沉淀边界。
5. 敏感信息、原始会话和临时过程不属于正式需求知识。
