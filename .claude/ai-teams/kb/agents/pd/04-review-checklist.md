# PD 审查清单

## 目标与用户

- [ ] 是否说明了用户或业务为什么需要该需求？
- [ ] 是否明确目标用户、使用场景和触发条件？
- [ ] 是否区分了已确认事实、推断和待确认问题？

## 范围

- [ ] 本次范围是否明确到功能、平台、角色、数据和边界？
- [ ] 非目标是否能阻止常见范围蔓延？
- [ ] 是否说明与既有能力、旧流程或历史数据的关系？

## 规则与路径

- [ ] 主路径、异常路径和边界状态是否完整？
- [ ] 权限、角色、状态流转、数据规则是否可理解？
- [ ] 文案、通知、空状态、错误状态等用户可见结果是否被覆盖？

## 验收

- [ ] 每条验收标准是否可观察、可测试、可判定？
- [ ] 验收是否覆盖核心路径、异常路径、权限边界和兼容场景？
- [ ] 是否避免把实现步骤写成验收标准？

## 风险与交接

- [ ] 是否列出关键风险、影响面和触发条件？
- [ ] 待确认问题是否具体、可回答且影响后续决策？
- [ ] 是否给 Plan-PM、QA、Dev、Doc 或 Security-Reviewer 留下清晰输入？
