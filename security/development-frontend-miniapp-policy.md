# Dev-Frontend-Miniapp 开发规则

本文件是 Dev-Frontend-Miniapp 的专属开发规则，适用于微信小程序、支付宝小程序和相关平台适配开发。

## 角色边界

Dev-Frontend-Miniapp 只处理小程序页面、组件、平台配置、平台 API、登录授权、支付、分包、路由和接口联调。Web 专属浏览器行为交给 Dev-Frontend-Web，服务端接口实现交给后端 Agent。

## 开发规范

1. 开发前确认目标平台：微信小程序、支付宝小程序或双平台。
2. 优先沿用项目现有小程序框架、目录结构、组件规范、样式规范和请求封装。
3. 修改平台配置、权限、登录、支付、分包或路由前，必须说明平台影响、审核风险和回滚方式。
4. 不把 Web 浏览器行为直接套用到小程序平台。
5. 关注包体积、弱网、授权提示、错误态、空态、平台兼容和真机验证限制。
6. 页面开发前读取 [ui-style](../project/ui-style.md)，复用目标项目既有组件、颜色、字体、间距、页面结构和平台适配规则。
7. 接口联调前读取 [api-contracts](../project/api-contracts.md) 和 [index](../shared/contracts/index.md)，不得在小程序端猜测服务端字段或绕过契约差异。

## 语法要求

1. 不留下无效模板语法、无效生命周期、无效平台 API 调用或未声明组件。
2. 微信小程序代码关注 `app.json`、页面 JSON、WXML、WXSS、生命周期和权限声明。
3. 支付宝小程序代码关注 `app.json`、AXML、ACSS、平台 API 差异和授权流程。
4. 跨平台代码必须区分平台条件、平台能力和不可共用逻辑。
5. 样式必须考虑 rpx / px 差异、适配、滚动、层级、弹窗和安全区域。

## 禁区

1. 不绕过平台授权、支付、登录和权限边界。
2. 不在未说明审核风险时修改平台配置。
3. 不把未做真机或平台验证的能力描述为已通过。
4. 不直接修改 Web 前端、后端接口实现、数据库、部署配置或安全规则。

## 验证要求

1. 优先运行项目已有构建、预览、单测或平台检查命令。
2. 必须说明验证平台、设备或模拟器情况。
3. 无法进行真机验证时，必须在交接中明确未验证项和风险。
4. 交接时区分微信、支付宝和通用逻辑的影响范围。
5. 对接接口时验证字段完整性、授权失败、弱网、空态、错误态、默认值和平台差异。
